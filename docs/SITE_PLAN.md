# 罗德岛表情簿 · 公开站完整方案 v2

更新：2026-09-23。当前站点：https://123rhodes-emotes.pages.dev/ 。
本版取代旧方案中独立的找表情/找篇目页面、独立统计页和米色偏后台视觉。GitHub main 推送后由现有 Cloudflare Pages Git 集成部署。

## 1. 定位与发布边界

《123罗德岛！？》二次元粉丝表情检索站。访客查角色、找篇目、浏览收录统计；漫画完整阅读跳转泰拉记事社对应篇目。

公开材料仅包含经过筛选的角色/篇目索引、人物 crop 展示副本、原始整列低清出处缩略图和统计。原漫画、内建 panel、SQLite、审核历史、模型与 embedding 留在内部。所有出现统计基于同一份已发布人工确认数据，不把角色 cast 当出现事实。

当前事实：仓库只有初版静态页面；没有公开 release.json、图像发布包或可执行的数据导出器。这一轮实现完整前端和发布数据读取协议，不从内部数据库擅自生成/公开素材。生产页面没有数据时明确显示待收录；测试数据只留在测试进程中。

## 2. 首页布局与视觉

从上到下：

1. 小型站点导航：站名、检索、收录统计、留言入口。
2. 顶部横向表情带：已发布 crop，随机/顺序，暂停/继续；悬停、键盘聚焦、后台标签页、减少动态效果时停止自动滚动。
3. 居中品牌标题与简短说明。
4. 大搜索框，紧邻“表情 / 篇目”切换；单一结果区。
5. 当前检索结果：表情网格或篇目卡片；返回/清除、继续加载。
6. 首页统计：四个总量、出场占比图、角色榜和趣味榜。
7. 留言准备状态、关于、来源、版权与隐私。

浅紫白背景，紫色主色、粉色和薄荷色点缀；网点、星形、票签、小贴纸边框构成二次元同人站气质。主标题、搜索、统计标题居中，卡片内部维持清楚的信息排列。无大幅漫画背景、假角色图片或虚构统计。未发布时顶部使用自制颜文字装饰卡，明确为等待收录的装饰。

桌面最大内容宽度约 1180px；手机单列搜索、双列表情图；减少动画设置生效。主文本保持可读对比度、所有主要控件支持键盘。背景、颜色和轮播参数独立配置。

## 3. 一个搜索入口

“表情”按角色名/已核实别名或篇目查找 crop；“篇目”按篇目名称、编号或其中已收录角色查找篇目。忽略英文大小写、首尾空格；篇目数字编号允许 57 / 057 匹配。

模式切换保留输入。按 Enter 提交，角色按钮/篇目按钮可以继续缩小范围。检索状态写入 URL，刷新和浏览器前后退恢复。大结果集分批显示，图片延迟加载。

每张表情展示角色名和篇目；悬停或键盘聚焦在旁边显示该 crop 来源整列的低清缩略图，窄屏通过“出处”按钮展开。点击图片或官方阅读链接前往经过核实的官方篇目，不展示后台 panel。

无结果、清单未发布、清单损坏/网络失败、图片缺失各自有简短提示。出错可重试；不把错误当真实零数量。

## 4. 首页统计与口径

基础统计为当前发布版本的总篇目、总表情实例、总角色、总来源图片。公开编号去重；基础数据不混用历史内部快照。图片数读取发布图片目录或显式图片总数；信息不足显示“—”。

| 榜单 | 定义 | 必需数据 |
| --- | --- | --- |
| 出场次数榜 | 每个角色已收录 instance 数降序 | instance.character_id |
| Episode 覆盖榜 | 出现的不同 episode 数降序 | instance.episode_id |
| 稀客榜 | 至少出现一次的角色，instance 数升序；零收录不入榜 | 同上 |
| 客串王 | 出现在不属于其本篇 cast 的篇目中的 instance 数 | 完整且可靠的本篇 cast |
| 无本篇客串榜 | 在任何本篇 cast 中都未登记，但有已收录出现的角色，按 instance 数降序 | 完整且可靠的本篇 cast |
| 久未出现榜 | 最后一次收录之后隔了多少个已发布篇目，降序 | 已核实的完整篇目时间顺序 |
| 最常见组合 | 两个角色共同出现的不同篇目数降序 | 已确认出现集合；不等同剧情亲密度 |
| 单篇出场记录 | 某角色在单个篇目中的 instance 数降序 | character × episode 计数 |

角色榜用选择器切换，前十名可点进检索。趣味榜在同一统计区展示。点击组合查看共同篇目中的两人，点击单篇记录查看该角色在该篇的图。

出场占比用环形图：前五位角色的 instance + 其余角色；图例显示数值和比例，并能点击角色。明确表示收录图数量的分布，不是故事重要性，也不等同不同表情类型数量。无有效数据不画假饼图。

cast 数据必须由发布清单明确声明完整，缺失时“客串王”“无本篇客串榜”不可用，并提示尚待补齐。不能把未知 cast 当空集合。顺序字段不完整或重复时“久未出现榜”不可用，不猜发布日期。这些前置条件和后续数据工作列在 README。

## 5. 统一人工改文案

唯一文案源：`content/copy.zh-CN.json`。每条包含稳定 key、`text` 和中文 `note`；站名、标题、搜索提示、按钮、空状态、统计解释、版权/隐私正文都在此。动态文本以 `{count}` 等命名占位符表示，修改时保留占位符。

运行 `python3 tools/build.py`，生成根目录 HTML。模板位于 templates/，CSS/JS 不复制散落的业务文案。构建检查缺失 key、重复 JSON key 和占位符，并 HTML 转义；文案不是 HTML，不可插入脚本。`--check` 检查生成文件是否与源一致。

生成结果和源文件一起提交，让现有无需构建命令的 Cloudflare Pages 集成继续工作。无需改账号或部署设置。README 给出改文案→生成→预览→提交的步骤。

## 6. 数据协议

继续读取 `config/site.json` 配置的发布清单。characters/episodes/instances 保留稳定 id，排除 NPC、临时身份和未确认项。每个 instance 关联角色、篇目、image_id、crop_url、source_preview_url、sort_key。图片路径只接受本站 /media/ 路径。

可选 images 是已发布源图的 id 目录，仅用于数量，不能包含原图路径。episodes 可带 cast_character_ids 和 order；清单 `cast_complete: true` 表示所有篇目 cast 已核实完整。缺字段的功能降级，已有基本检索继续工作。

完整数据合同见 `docs/DATA_CONTRACT.md`。不读取内部 DB，不在浏览器计算模型或写回身份。统计在当前约五千实例规模下从公开数据计算，后续规模增长再考虑离线预计算。

## 7. 留言、版权与隐私

本轮保留留言区的未开放状态；没有配置后端就不显示可提交表单。后续匿名留言只显示正文和时间，人工审核后公开，不建设用户账号、补框、在线改标签、上传图片。

版权页延用既有非官方粉丝站说明，官方素材与原创文字的许可分开。访客统计沿用 Cloudflare 平台能力，启用自定义统计前更新隐私说明。站点不声称版权声明就是授权。

## 8. 本轮验收和部署

先更新方案，再改共享模板、样式、搜索/统计与文案构建。用浏览器检查桌面/手机、空清单、正常清单、失败重试、统一搜索、别名/编号、来源预览、分页、统计和下钻、轮播暂停、减少动态效果。测试清单使用虚构名称，仅在测试请求中注入，不进部署文件。

检查生成文件、Git diff 和公开文件范围；commit/push 到现有 main，验证 Pages 新页面部署。没有公开清单时新样式可以上线，数字和真实表情须待公开发布包接入。
