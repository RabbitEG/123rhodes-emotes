# 罗德岛表情簿 · 公开站完整方案 v3

更新：2026-09-23。当前站点：https://123rhodes-emotes.pages.dev/ 。
本版按最新反馈明确：统一搜索入口，独立搜索结果页；顶部按实例持续慢速横向滚动；接入真实人工数据库。GitHub 仅保留代码，经筛选的公开索引和展示素材另发 Cloudflare R2。GitHub main 推送后由现有 Pages 集成部署页面代码。

## 1. 定位与发布边界

《123罗德岛！？》二次元粉丝表情检索站。访客查角色、找篇目、浏览收录统计；漫画完整阅读跳转泰拉记事社对应篇目。

公开材料仅包含经过筛选的角色/篇目索引、人物 crop 展示副本、原始整列低清出处缩略图和统计。原漫画、内建 panel、SQLite、审核历史、模型与 embedding 留在内部。所有出现统计基于同一份已发布人工确认数据，不把角色 cast 当出现事实。

当前已用只读 SQLite 连接导出真实数据：339 篇、4,803 个具名人物实例、368 位角色、683 张来源图。排除 120 个 NPC 实例；图像导出无缺失。全部官方篇目 URL 与原始目录精确匹配，顺序也与本地编号相符。公开副本只保存在忽略的 publish/site/；线上通过 media → 123rhodes-db binding 读取，等待上传素材，不上传 GitHub。

## 2. 首页布局与视觉

从上到下：

1. 小型站点导航：站名、检索、收录统计、留言入口。
2. 顶部横向表情带：每张卡片恰好一个真实 instance，默认每秒 22px 从右向左持续滚动，通过重复同一序列无缝循环。随机/顺序只影响卡片排列，不再定时整组跳动。悬停、聚焦、手动暂停、后台标签页及减少动态效果时停止；保留手动往后查看。
3. 居中品牌标题与简短说明。
4. 大搜索框，紧邻“表情 / 篇目”切换；提交后进入 /search.html。
5. 首页不插入结果列表。独立结果页复用搜索控件，展示表情网格或篇目卡片，支持清除、继续加载和返回首页。
6. 首页统计：四个总量、出场占比图、角色榜和趣味榜。
7. 留言准备状态、关于、来源、版权与隐私。

浅紫白背景，紫色主色、粉色和薄荷色点缀；网点、星形、票签、小贴纸边框构成二次元同人站气质。主标题、搜索、统计标题居中，卡片内部维持清楚的信息排列。无大幅漫画背景、假角色图片或虚构统计。未发布时顶部使用自制颜文字装饰卡，明确为等待收录的装饰。

桌面最大内容宽度约 1180px；手机单列搜索、双列表情图；减少动画设置生效。主文本保持可读对比度、所有主要控件支持键盘。背景、颜色和轮播参数独立配置。

## 3. 一个搜索入口

“表情”按角色名/已核实别名查找该角色的 crop，不把标题匹配篇目里的其他角色混进结果；“篇目”按篇目名称、编号或其中已收录角色查找篇目，点击后浏览该篇的所有收录 crop。忽略英文大小写、首尾空格；纯数字编号 57 / 057 精确匹配同一篇，不混入157/257。

首页模式切换保留输入，按 Enter 才导航到 /search.html?mode=…&q=…。结果页内可继续切换和搜索；角色/篇目/组合入口同样进入独立结果页。状态写入 URL，刷新和浏览器前后退恢复。大结果集分批显示，图片延迟加载。

每张表情展示角色名和篇目；悬停或键盘聚焦在旁边显示该 crop 来源整列的低清缩略图，窄屏通过“出处”按钮展开。点击图片或官方阅读链接前往经过核实的官方篇目，不展示后台 panel。

无结果、清单未发布、清单损坏/网络失败、图片缺失各自有简短提示。出错可重试；不把错误当真实零数量。

## 4. 首页统计与口径

基础统计为当前发布版本的总篇目、总表情实例、总角色、总来源图片。公开编号去重；基础数据不混用历史内部快照。图片数读取发布图片目录或显式图片总数；信息不足显示“—”。

| 榜单 | 定义 | 必需数据 |
| --- | --- | --- |
| 出场次数榜 | 每个角色已收录 instance 数降序 | instance.character_id |
| 篇目覆盖榜 | 角色出现过的不同篇目数降序 | instance.episode_id |
| 稀客榜 | 至少出现一次的角色，instance 数升序；零收录不入榜 | 同上 |
| 客串王 | 出现在不属于其本篇 cast 的篇目中的 instance 数 | 完整且可靠的本篇 cast |
| 无本篇客串榜 | 在任何本篇 cast 中都未登记，但有已收录出现的角色，按 instance 数降序 | 完整且可靠的本篇 cast |
| 久未出现榜 | 最后一次收录之后隔了多少个已发布篇目，降序 | 已核实的完整篇目时间顺序 |
| 双向奔赴 | 共同篇目数 ÷ 双方出现篇目的并集（Jaccard），至少共同出现两篇 | 已确认出现集合；不等同剧情亲密度 |
| 单相思 | 分别计算共同篇目数 ÷ A 的篇目数、共同篇目数 ÷ B 的篇目数，按两者差距排序 | 已确认出现集合；不等同剧情亲密度 |
| 单篇出场记录 | 某角色在单个篇目中的 instance 数降序 | 角色 × 篇目计数 |

角色榜用选择器切换，每榜显示前 30 名并可点进检索。出场占比图显示前十位干员及其余角色。趣味榜列出前 30 组双向篇目重合率、前 30 组双方篇目共现率差异，以及前 30 条单篇出场记录。点击组合查看共同篇目中的两人，点击单篇记录查看该角色在该篇的图。

出场占比用环形图：前十位角色的 instance + 其余角色；图例显示数值和比例，并能点击角色。明确表示收录图数量的分布，不是故事重要性，也不等同不同表情类型数量。无有效数据不画假饼图。

双向奔赴综合分＝Jaccard × 共同篇目数，兼顾比例和持续共现篇数；单相思综合分＝双方共现率差 ×（较少一方篇目数 ÷ 较多一方篇目数），降低超高频角色的占榜。两组关系榜只列至少共同出现两篇的组合。共现只描述已收录篇目分布，不解释为剧情亲密程度。

cast 数据必须由发布清单明确声明完整，缺失时“客串王”“无本篇客串榜”不可用，并提示尚待补齐。不能把未知 cast 当空集合。顺序字段不完整或重复时“久未出现榜”不可用，不猜发布日期。这些前置条件和后续数据工作列在 README。

## 5. 统一人工改文案

唯一文案源：`content/copy.zh-CN.json`。每条包含稳定 key、`text` 和中文 `note`；站名、标题、搜索提示、按钮、空状态、统计解释、版权/隐私正文都在此。动态文本以 `{count}` 等命名占位符表示，修改时保留占位符。

运行 `python3 tools/build.py`，生成根目录 HTML。模板位于 templates/，CSS/JS 不复制散落的业务文案。构建检查缺失 key、重复 JSON key 和占位符，并 HTML 转义；文案不是 HTML，不可插入脚本。`--check` 检查生成文件是否与源一致。

生成结果和源文件一起提交，让现有无需构建命令的 Cloudflare Pages 集成继续工作。无需改账号或部署设置。README 给出改文案→生成→预览→提交的步骤。

## 6. 数据协议

使用 Pages Functions + R2 binding：`media` → `123rhodes-db`。publicDataBaseUrl 保持空值，浏览器从同域 /data/release.json 与 /media/ 读取，无需公开 bucket/CORS。characters/episodes/instances 保留稳定 id，排除 NPC、临时身份和未确认项。每个 instance 关联角色、篇目、image_id、crop_url、source_preview_url、sort_key。Function 只开放公开清单及内容哈希 WebP，不暴露任意 bucket 文件。

可选 images 是已发布源图的 id 目录，仅用于数量，不能包含原图路径。episodes 可带 cast_character_ids 和 order；清单 `cast_complete: true` 表示所有篇目 cast 已核实完整。缺字段的功能降级，已有基本检索继续工作。

完整数据合同见 docs/DATA_CONTRACT.md。tools/export_public.py 只读 SQLite 一致快照，解析合并关系，只导出有效人工确认身份；不写数据库。Pillow 重新编码 crop（最长边512px）和整列缩略图（宽180px、长边640px双限制），去除元数据。tools/upload_r2.py 只上传清单引用的5,486份展示文件，最后发布索引，支持跳过已存在的哈希文件，不删除历史对象。浏览器不接触 SQLite、模型或人工写操作。

内部 cast 包含所有已确认出场，不能直接当作“本篇主角”做客串排名；当前发布包 cast_complete=false。可靠的出场/篇目/稀客/久未出现/共现/单篇记录正常提供。

## 7. 留言、版权与隐私

留言板使用独立 D1 和 Pages Functions，未配置 D1、Turnstile sitekey/secret、审核密钥时不显示可提交表单。匿名留言只公开正文和时间，先入待审核，由站长在私用审核页批准或排除；不建设访客账号、补框、在线改标签、上传图片。具体配置见 docs/GUESTBOOK_SETUP.md。

版权页延用既有非官方粉丝站说明，官方素材与原创文字的许可分开。访客统计沿用 Cloudflare 平台能力，启用自定义统计前更新隐私说明。站点不声称版权声明就是授权。

## 8. 本轮验收和部署

先更新方案，再改共享模板、样式、搜索/统计与文案构建。用浏览器检查桌面/手机、空清单、正常清单、失败重试、统一搜索、别名/编号、来源预览、分页、统计和下钻、轮播暂停、减少动态效果。测试清单使用虚构名称，仅在测试请求中注入，不进部署文件。

用 tools/preview.py 在本地把页面和真实发布包组合预览。测试两类数据：内存虚构清单用于统计边界；真实导出用于图片、来源与搜索核验。检查生成文件、Git diff，commit/push 只包含代码；Pages 配置 media binding，R2 上传公开包后接通。步骤见 docs/R2_SETUP.md。缺上传凭据时只停止上传，不把素材转存 GitHub。
